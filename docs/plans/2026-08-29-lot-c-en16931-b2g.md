# Plan : Lot C — Champs EN 16931 + B2G structuré

## Contexte projet
- Module : **Trust Context** (`apps/trust-api`) + `packages/db` (**migration additive**). Touche `createInvoiceSchema`, `invoiceLineSchema`, `createDraft`, `document-renderer` (Lot A), le chemin USSD Option 6.
- Persona : entrepreneur sur marché public (K3). Pas de nouveau persona.
- Données sensibles : aucune. Tous les nouveaux champs sont **déclaratifs, recopiés sans vérification** — même discipline qu'`Invoice.referenceMarche` (ADR-090).
- Impact réglementaire : prépare l'alignement EN 16931 (business terms) et l'export UBL 2.1 (ADR-053, V2), attendus pour l'agrément PDP Q3 2027.

## Décision produit (validée par l'utilisateur, à tracer en ADR-109)
Le Backlog/ERD/ADR ne spécifient QUE `reference_marche` (K3/ADR-090) côté B2G. Les autres champs (bon de commande, contrat, engagement, cadre, codes produit ligne, codes UNTDID) sont ajoutés sur **décision explicite du propriétaire produit** pour aligner facture.gn sur les *business terms* EN 16931 en vue de l'export UBL 2.1 (ADR-053) et de l'agrément PDP. **ADR-109 rédigé dans `V/Registre-ADR-facture-gn.md`** pour que cet ajout ne soit pas une exigence silencieusement inventée.

## Mapping EN 16931
| Champ facture.gn | Business term EN 16931 | Statut |

| `reference_marche` (existe, K3) | BT-17 — Tender or lot reference | inchangé |

| `cadreFacturation` (nouveau, enum) | marqueur de contexte B2G explicite (`standard` / `marche_public`), non-dérivé du client | ajouté |

## Clarifications
- Q : `cadreFacturation = marche_public` doit-il rendre `referenceMarche` obligatoire ? → R : **non** — ADR-090 impose `reference_marche` optionnel (K3 l'a implémenté ainsi, la cohérence est vérifiée humainement par le DAF). Aucune règle cross-field bloquante ; tous les champs restent déclaratifs.
- Q : la génération récurrente (I1) porte-t-elle ces champs ? → R : **non** — `RecurringInvoiceTemplate` ne les stocke pas ; les factures générées auront `cadreFacturation: standard` + nuls. Suivi possible (ajouter au template) hors Lot C.
- Q : USSD Option 6 pose-t-elle `cadreFacturation` ? → R : **oui** — `emitInvoice()` gagne un param `cadre` ; le handler Option 6 (`handlePublicOrderReference`) passe `"marche_public"`, Option 4 garde `"standard"`.
- Q : `untdidTypeCode` — où l'utiliser ? → R : dans le PDF de facture (Lot A) : ligne "Type de document" avec le code entre parenthèses quand non-null. Donne un vrai appelant au helper, cohérent EN 16931 sur le document opposable.
